# PHP vulnerability exposure assessment

Reviewed October 22, 2026 for CVE-2026-109618 and CVE-2026-109619. The stock
Brew-Web application uses Python/Flask/Gunicorn and contains no PHP application
code, Composer dependencies or PHP web-server configuration. A PHP patch is not
applicable to that application stack. This is a scoped exposure assessment, not
a claim that every component is free of vulnerabilities.

## Advisory and applicability

The [PHP security advisory](https://www.php.net/archive/2026.php)
and the upstream advisories for
[CVE-2026-109618](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w)
and [CVE-2026-109619](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp)
describe remote-code-execution flaws in PHP request processing. A vulnerable PHP
runtime is required; a Python application is not made vulnerable merely by
serving HTTP. Disabling PHP features is not a substitute for vendor patches on
systems that actually run affected PHP.

## Verification procedure

### Recorded result

[GitHub assessment run 39774102309](https://github.com/anndrox/brew-web/actions/runs/39774102309)
passed on October 22, 2026 for script/workflow source
`e2285936af920e913ada3cb92e1b9549fcbade18`:

- Published web image: PASS, no PHP commands/packages/matching runtime files.
- Shared PostgreSQL/export image: PASS, same absence checks.
- Deliberate PHP command marker: refused with the expected detector message;
  its disposable container was removed.

Conclusion: the reviewed stock images are **not affected** by these two PHP
advisories because the required PHP component is absent. This does not assert
that PHP was patched or that unrelated vulnerabilities are absent.
[PR #38](https://github.com/anndrox/brew-web/pull/38) records the final CI and
publication evidence for the assessment and regression gates.

### Repeating the check

`.github/workflows/php-exposure.yml` pulls the two exact public images on a
GitHub-hosted runner. `tests/security/verify_no_php.sh` overrides their normal
entrypoints and runs only the inventory script with UID/GID 65534, a read-only
root filesystem, no network, dropped capabilities and no host-data mounts.
It never starts Brew-Web or PostgreSQL, connects to a database, or publishes
ports. Any Docker-created anonymous image volume is empty and removed with its
disposable container. No local Docker Desktop is used.

The check refuses PHP commands, installed PHP packages, or matching PHP runtime
files under standard executable/library locations. An intentional negative test
adds a harmless `php` command marker in container-local temporary storage, checks
that it is rejected, and removes that disposable container. The original images
remain unchanged; no exploit or affected PHP runtime is installed.

The same check guards future candidate builds and post-publish verification.
Workflow logs and the linked assessment pull request record execution results.
No successful runtime check is claimed until its exact-SHA workflow passes.

## Operator actions and limits

- Existing stock v1.4.2 users do not need a PHP-specific image update or database
  migration for these two advisories. Do not replace or delete data volumes.
- Custom images, bind-mounted executables, separate web servers, reverse proxies,
  NAS management software and other PHP applications are not covered by this
  project inventory. Check them independently with their owners/vendors; do not
  assume they are safe merely because Brew-Web itself does not use PHP.
- If any of those components run PHP, apply the relevant vendor security update
  and restart affected services following that vendor's guidance. This project
  change does not authorize host, proxy, runner-infrastructure or production
  changes.
- Package and filename checks are defense in depth, not a malware scan or proof
  against renamed/custom embedded runtimes. The result applies to the exact
  reviewed stock images and sources, not every future image or third-party fork.
- The separate documented Quill advisory remains subject to its existing
  application-level mitigations; a PHP non-applicability result is not an
  all-language clean security audit.

Publication consists of this assessment and regression checks. There is no
affected PHP component to patch and no PHP-fix container release to recommend;
v1.4.2 and its immutable digest remain unchanged.
